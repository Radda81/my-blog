# Review 지침: apps/pixel-art

## 범위
- 이 지침이 허용하는 범위는 오직 `D:\ClaudeCode\my-blog\apps\pixel-art\` 폴더 내부뿐이다.
- 블로그의 다른 파일(`apps/2048/` 포함)은 절대 수정하지 않는다.
- 문제를 발견하면 이 폴더 안에서 직접 수정해도 된다 (범위 내에서는 Edit/Write 허용).

## 할 일
1. `apps/pixel-art/spec.md`를 읽고 사양을 파악한다.
2. `index.html`, `style.css`, `script.js` 코드를 사양과 대조해 검토한다 — 특히 Pointer Events 처리, Bresenham 라인 알고리즘, 좌표 clamp, 지우개가 실제로 투명 처리되는지(clearRect만 하고 fillRect 안 함), PNG 내보내기 로직.
3. 브라우저에서 실제로 동작을 검증한다:
   - 로컬 정적 서버로 `apps/pixel-art/`를 서빙해서 열어본다 (Node.js는 `C:\Program Files\nodejs\node.exe`에 있으나 PATH에 없으므로 전체 경로로 실행. 임시 서버 스크립트는 스크래치 디렉터리에 만들고 apps/pixel-art/ 안에는 두지 말 것).
   - 클릭으로 칸 칠하기, 드래그로 이어 칠하기(빠른 드래그도 중간 칸이 안 빠지는지), 팔레트 색 전환, 지우개(투명 처리 확인), 커스텀 컬러 피커, 전체 지우기(확인창 포함) 동작을 확인한다.
   - PNG로 저장을 실제로 눌러서 다운로드되는 파일이 진짜 16x16 픽셀인지, 칠한 색이 맞는지, 미채색 부분이 흰색이 아니라 투명(알파 채널 있음)인지 확인한다 — 가능하면 다운로드된 파일을 직접 읽어(예: Node.js로 PNG 헤더/픽셀 검사) 확인한다.
   - 모바일 뷰포트(예: 375px)에서 레이아웃이 깨지지 않는지 확인한다.
   - 콘솔 에러가 없는지 확인한다.
4. 문제를 발견하면 apps/pixel-art/ 안의 파일을 직접 고치고, 고친 뒤 다시 확인한다.
5. 결과를 `apps/pixel-art/review.md`로 작성한다: 검증한 항목들, 발견한 문제와 수정 여부, 최종 결론(정상 동작 여부).
